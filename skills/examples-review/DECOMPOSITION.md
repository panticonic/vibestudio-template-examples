# Review an Examples workspace

The Examples template contains three persistent game engines. A reviewer needs
to separate what a player can currently see, what the public state has already
settled, and what an illustration or forecast purports to depict.

| Concern | Implementation |
| --- | --- |
| Select the applicable game contract | The root dispatches the typed request to Adventure, Grimoire or Regency. |
| Adventure availability | Inspect the actual actor-scoped view. Recognize visible exits, inventory and document access. A closed container can make an entity unobservable. |
| Adventure continuity | Compare explicit pre- and post-action readbacks. An unchanged viewpoint can still have advanced fictional time. |
| Adventure artwork | Compare captured and current scene signatures and place identity. A stale illustration may coexist with valid gameplay. |
| Grimoire habitat and care | Interpret current home, habitat conditions and settled days against the resident's observed requirements. |
| Grimoire interaction and ecology | Review a bounded visit or pulse, distinguishing a state transition from a repeated tap or an untouched state. |
| Regency settlement | Interpret real month-end accounts, routes and regional measures. Distinguish paid capacity, actual movements and progress on works. |
| Regency projection | Interpret a separate forecast and committed world without equating projected numbers with historical results. |
| Compose multiple demonstrations | Review each distinct claim through its owning game subtree, then combine the outcomes and preserve their ordered supporting evidence. |
| Exact evidence | Plain fixture code captures public engine observations. The harness checks the decision, finding and reported evidence identities independently. |

The task bank starts from original Examples assets and deterministic public
engine operations. The Natlang program receives detached readbacks. Host code
and template services retain control of durable state and gameplay.

The live Grimoire branch gets its evidence through one caller-bound read leaf. It
builds each garden comparison using the unchanged observations, calls the existing
habitat or transition reviewer, and combines every finding in claim order. The
managed harness runs visits and clock changes through the actual panel. The
quiet observation action advances the installed garden without waking a
storyteller. The live tasks read
the persisted garden before and after. The independent reference verifies
the elapsed phases, attachment gained on distinct days, and each authored
claim about recognition, settlement, weather, or discoveries.

The live Adventure branch reads the same journey's opening baseline and saved
current view through one caller-bound service. It passes each claim into the
existing access, continuity or illustration lambda and combines the findings.
The worker provides the actor-visible projection and canonical scene signature.
The managed harness opens the assigned campaign panel when artwork is expected
and independently joins its loaded image to the worker's stored illustration.
An unpainted opening supplies a separate check for missing artwork.
